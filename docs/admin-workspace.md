# Панель администратора

Панель администратора — отдельное рабочее место для управления системными данными учебного тренажёра. Она не участвует в проведении занятия и не подменяет кабинет преподавателя: администратор поддерживает пользователей, справочники, интеграции и контролирует техническое состояние системы.

## Доступ и границы

- Frontend открывает административный интерфейс в отдельном shell `/admin`.
- Все административные запросы используют REST-префикс `/api/admin`.
- Каждый endpoint самостоятельно проверяет роль `ADMIN`; скрытое меню не считается защитой.
- Последнего активного администратора нельзя удалить, деактивировать или лишить административной роли.
- Пароли и AI API key никогда не возвращаются клиенту и не записываются в аудит в открытом виде.

## Основные разделы

- **Обзор** — сводные показатели пользователей, служб, объектов, сценариев, импортов и состояния AI.
- **Пользователи** — создание и редактирование администраторов, преподавателей и диспетчеров, управление ролями, паролями, активностью и учебными группами пользователей.
- **Классификатор** — просмотр и редактирование правил классификации происшествий и связанных служб.
- **Службы 112** — каталог служб и организаций, используемых маршрутизацией и сценариями.
- **Объекты Москвы** и **Типы объектов** — управление объектным реестром и его иерархическим справочником.
- **Импорт данных** — экспорт версионированных наборов, подтверждаемый идемпотентный импорт и история запусков без автоматического удаления отсутствующих записей.
- **AI** — выбор провайдера и модели, настройка endpoint, write-only API key, проверка подключения и статистика использования.
- **Сценарии** — общая с преподавателем библиотека `ScenarioTemplate`: поиск, фильтрация, создание, редактирование черновиков, публикация, копирование и архивирование.
- **Аудит** — человекочитаемая история административных изменений с автором, временем и состояниями до/после.
- **Система** — состояние сервисов, версия приложения, Git commit, ревизия БД, окружение и серверное время.

## Как проходят изменения

Интерфейс отправляет команду в административный endpoint, backend повторно проверяет роль и бизнес-ограничения, затем изменяет канонические модели в транзакции. Значимые операции создают неизменяемую запись `AdminAudit`. После успешной команды frontend перечитывает состояние через REST; отображаемое состояние не считается источником бизнес-правил.

Справочники можно изменять вручную через валидируемые формы или восстанавливать из версионированных seed/import-файлов. Импорт создаёт и обновляет записи по устойчивым ключам, но не удаляет данные только потому, что они исчезли из очередного файла.

## Интерфейс

Слева расположено постоянное меню разделов, справа — заголовок выбранного раздела и рабочая область. Верхний правый блок даты, московского времени, выбора пользователя и выхода переиспользует реализацию рабочего места диспетчера ДДС. Визуальные состояния, таблицы, формы и модальные окна используют общую служебную палитру тренажёра.
