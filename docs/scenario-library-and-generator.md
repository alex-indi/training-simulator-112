# Библиотека шаблонов и генерация карточек MVP

**Статус:** описание действующего пользовательского процесса. Технические поля старого Scenario Engine описаны отдельно в [legacy-документе](scenario-engine.md) и не определяют обычный интерфейс преподавателя.

## Основной поток

```text
Шаблон инцидента → генерация нескольких карточек → предварительный просмотр →
сохранение в библиотеку или добавление в занятие → общий/личный пул → Incident
```

Преподаватель выбирает занятие и группу, затем шаблон и количество карточек. Генератор выбирает реальные объекты из Object Registry, допустимые значения условий и службы по правилу классификатора. Преподаватель просматривает каждую карточку: объект, адрес, условия и текст ДДС. Он может изменить условия, исправить или перегенерировать текст, перегенерировать карточку, исключить её, сохранить в библиотеку либо добавить набор в занятие. Сохранённая карточка повторно используется через копию snapshot.

`SHARED_QUEUE` — основной режим MVP: карточки группы готовятся до подключения обучаемых, а первый claim закрепляет выданную карточку за одним АРМ. `INDIVIDUAL_QUEUE` также поддерживается. Случайный порядок меняет только последовательность уже подготовленных карточек; содержимое при выдаче не генерируется.

## Данные шаблона

Обычный шаблон задаёт название, тип происшествия из SRC-006, тип объекта, сложность и допустимые варианты фактов. Классификатор определяет связанные службы; шаблон не создаёт новые службы и не содержит универсальный порядок действий ДДС, `expected_actions` или пользовательский конструктор assessment. Внутренние статусы `DRAFT`/`READY`/`CONFIRMED` не являются обязательными шагами интерфейса преподавателя.

Источники данных имеют разные роли:

- SRC-006 определяет **что произошло** и связанные службы.
- Object Registry определяет **где произошло**: реальный объект и адрес.
- Варианты фактов задают **условия конкретной карточки**.
- Snapshot карточки фиксирует выбранные данные и текст до занятия.

Службы определяются проверенными связями классификатора и сохраняются в snapshot. Реакция другой службы по умолчанию — принятие карточки; явно заданная `initial_reaction` в snapshot может заменить это значение. Отсутствующая в snapshot служба не появляется. Реакция не зависит от runtime ID инцидента.

## Карточка и runtime

В коде шаблон хранится как `ScenarioTemplate`, конкретная подготовленная карточка — как `ScenarioInstance`, выдача обучаемому — как `Incident`. Один `ScenarioInstance` соответствует одной подготовленной карточке с фиксированными объектом, условиями, текстом и составом служб. Изменение исходного шаблона не переписывает подготовленные или сохранённые карточки.

После принятия `Incident` основная учебная бригада 101 проходит этапы выезда, прибытия, работ и завершения по учебному времени. Их выпускает `TRAINING_BRIGADE`, а не timeline шаблона. Паузы занятия и АРМ исключаются из учебного времени. Состояние бригады и сообщения других служб сохраняются как факты истории; они не меняют DDS status автоматически. ДДС вручную выставляет статусы и завершает карточку. Assessment сопоставляет его действия с фактическими сообщениями, после чего преподаватель подтверждает итог.

AI может сформулировать текст исходной карточки и резюме оценки по уже рассчитанным фактам. Классификация, выбор объекта и служб, реакции, переходы статусов и оценочные правила остаются на backend; при недоступном AI работает детерминированный fallback.

## Legacy/internal Scenario Engine

В БД и backend пока сохранены `ScenarioEvent`, `ScenarioEventTemplate`, `ScenarioRuntimeEvent`, ручные `RESPONSE_MESSAGE`, `offset_seconds`, `target_response_state`, `expected_actions` и критерии старого сценарного конструктора. Это совместимость с ранее подготовленными данными и внутренние возможности, а не MVP workflow преподавателя. Обычный список шаблонов скрывает варианты с исполняемыми runtime-событиями; исходное `INITIAL_REPORT` может оставаться в старом seed, но не создаёт отдельного сообщения при выдаче.

Новые demo-шаблоны и упрощённый путь подготовки карточек не должны программировать ход служб или дублировать сообщения бригады 101. Старые таблицы сохраняются; рискованная миграция ради их удаления не требуется.
