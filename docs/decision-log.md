# Decision Log

Короткая хронология значимых продуктовых и инженерных решений.

ADR используется для крупных архитектурных решений. Decision Log — для быстрых, но долговременных договорённостей.

## 2026-09-21 — Основной обучаемый: диспетчер ДДС

**Тип:** PRODUCT / DOMAIN

Основной MVP строится вокруг диспетчера ДДС, который получает уже сформированную карточку.

Оператор первичного приёма Службы-112 не является основным обучаемым этого потока.

## 2026-09-21 — Разделяем реальный факт и учебную реализацию

**Тип:** ENGINEERING PRINCIPLE

Подтверждённые процессы заказчика храним отдельно от решений тренажера.

Например, реальный канал связи — телефон/радио/внутренние средства; онлайн-чат — только реализация MVP.

## 2026-09-21 — Виртуальная группа реагирования

**Тип:** PRODUCT_DECISION

Для первого MVP создаём `ResponseUnit`, которому обучаемый назначает задачу через `ResponseAssignment`.

Группа симулирует работу, состояние конкретного реагирования хранится в `ResponseAssignment`, а обучаемому передаются сообщения о ходе работ.

## 2026-09-21 — Онлайн-чат как замена телефонного канала

**Тип:** PRODUCT_DECISION

Первый MVP использует встроенный чат между диспетчером и виртуальным старшим группы реагирования.

Причина: заказчик подтвердил телефонную коммуникацию и допускает упрощение до телефона, а полноценная телефония не нужна для проверки основного учебного workflow.

Последствие: доменная модель коммуникации не должна зависеть от конкретного transport. Позднее чат можно дополнить/заменить `TelephonyProvider`.

## 2026-09-21 — Состояние группы и статус карточки независимы

**Тип:** PRODUCT_DECISION

`ResponseAssignment.EN_ROUTE` не переводит карточку автоматически в `Начало реагирования`.

Обучаемый должен сам прочитать сообщение и выполнить действие. Это является частью оценки.

## 2026-09-21 — TrainingScenario вместо Scenario

**Тип:** NAMING

Учебная сущность называется `TrainingScenario`, потому что термин «сценарий реагирования» уже используется в материалах реальной Системы-112 в другом смысле.

## 2026-09-21 — Маршрутизация учитывает территорию и подчинённость

**Тип:** DOMAIN / ARCHITECTURE

Будущий routing не должен сводиться к `incident_type → service`.

Нужно предусмотреть район обслуживания и ведомственную подчинённость объекта.

Полный RoutingEngine не блокирует первый vertical slice.

## 2026-09-21 — Git является памятью проекта

**Тип:** WORKFLOW

Проект разрабатывается двумя людьми на нескольких устройствах.

Чат Codex считается временным. Долговременное состояние хранится в Git:

- знания — `docs/`;
- состояние `main` — `docs/current-state.md`;
- состояние активной задачи — `tasks/UT112-xxx.md`;
- workflows Codex — `.agents/skills/`.

## 2026-09-21 — Checkpoint commits разрешены

**Тип:** WORKFLOW

Перед сменой устройства незавершённую, но полезную работу разрешено фиксировать промежуточным коммитом и push в feature-ветку.

История `main` остаётся чистой за счёт squash merge.
