# Текущее состояние `main`

**Проверено по дереву `main`:** 26.09.2026. Здесь описана реализация, а не целевая модель. Источник требований для следующего изменения подготовки занятия — [новый workflow преподавателя](instructor-preparation-workflow.md).

## Продуктовый путь

ADMIN настраивает пользователей и справочники → INSTRUCTOR создаёт занятие и подготавливает пакет карточек → TRAINEE получает карточку, принимает решение ДДС и взаимодействует с виртуальной группой → INSTRUCTOR наблюдает занятие и подтверждает разбор.

Основной обучаемый — диспетчер ДДС. Карточку он получает готовой; статусы своей службы меняет сам. Состояние виртуальной группы и сообщения не меняют его статус автоматически.

## Реализовано

- FastAPI, SQLAlchemy 2, Alembic, PostgreSQL; React, Vite и CSS Modules. `dev.py` перед локальным запуском применяет миграции. `app.scripts.bootstrap_demo` восстанавливает чистую БД из CORE/DEMO seed. REST хранит каноническое состояние; Socket.IO уведомляет клиент.
- Занятия `TrainingSession`, участия `TrainingRun`, группы занятия `TrainingGroup`; режимы `FLOW`, `FIXED_SET`, `MANUAL`; личные и общие очереди с атомарным claim. Текущий мастер подготовки привязывает часть работы к подключённым обучаемым и АРМ.
- Карточки `Incident` со snapshot источника, статусами ДДС, `available_actions`, обязательными комментариями и неизменяемой историей `IncidentAction` с серверными метками.
- Виртуальные `ResponseUnit`, назначения `ResponseAssignment`, адресные сообщения `ResponseMessage`, чат и подготовленные runtime-события. Группа не переводит статус ДДС автоматически.
- Кабинет преподавателя: подготовка занятия и очередей, Live Monitor, глобальная и личная паузы, ручные команды, заметки, завершение занятия, предварительная детерминированная оценка и подтверждаемый преподавателем итог с аудитом.
- SRC-006, каталог служб, дерево типов объектов и московский Object Registry восстанавливаются из версионированных файлов. В чистом bootstrap — 1 283 правила классификатора, 209 служб, 12 типов и 4 638 объектов.
- Библиотека `ScenarioTemplate` (`DRAFT`, `READY`, `ARCHIVED`), генерация `ScenarioInstance`, просмотр и правка пакета до утверждения. READY не редактируется на месте; архивирует его автор или ADMIN.
- `AITextRenderer` с OpenAI и OpenAI-compatible адаптерами, сохранением готовых текстов и детерминированным fallback. AI не выбирает бизнес-факты; ключ хранится только на backend.
- Панель `/admin` для пользователей, справочников, импорта/экспорта, библиотеки сценариев, настроек AI и аудита; доступ защищён проверкой роли на backend.
