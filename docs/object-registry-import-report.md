Сформированы 15 767 атрибутов и 10 511 тегов. Каждый объект содержит `source`, `source_dataset_id`, `external_id` и ссылку на существующий `ObjectType`. В реестре станции имеют ключ `station:<NameOfStation>`; в атрибуте `source_entrance_ids` сохранены идентификаторы всех вошедших в группу записей. Входы агрегированы по полю `NameOfStation`. Координата станции — среднее координат её входов в Москве, ориентир для поиска, а не точное местоположение платформы.

## Качество и ограничения

- Набор 747 не содержит структурированных координат, района и административного округа. Все 3492 объекта оставлены без этих полей; адрес взят из `yuridich_adress` без геокодирования.
- 368 образовательных записей не имеют однозначного соответствия школе/детскому саду/смешанному учреждению. Они сохранены как `EDUCATION_UNKNOWN` с атрибутом `needs_review=true`; ни одна запись не отброшена.
- 11 входов из набора 624 помечены источником как расположенные вне Москвы. Они не входят в московский seed: 3 входа станции «Мякинино» целиком исключили эту станцию; остальные относятся к «Новокосино» (2) и «Котельники» (6), у которых есть входы в Москве. Причина исключения зафиксирована здесь, исходные строки сохранены.
- У 67 станций входы относятся к нескольким районам. В поле `district` не выбран произвольный район; полный набор районов хранится в атрибуте `districts`.
- В наборе 624 нет входов с отсутствующими координатами; дублирующихся ключей `source` + `external_id` в подготовленном seed нет.
- Теги `children` и `mass_people` назначены типам `SCHOOL`, `KINDERGARTEN`, `EDUCATIONAL_COMPLEX`; неопределённый образовательный тип получает только `education` до проверки. Станции получают `transport`, `underground`, `mass_people`.

## Воспроизведение

Из `backend/`:

```bash
uv run python -m scripts.import_city_objects.import_objects build
uv run alembic upgrade head
uv run python -m scripts.import_city_objects.import_objects load
```

`build` создаёт четыре файла в `backend/seed/city_objects/`: `city_objects.json`, `object_attributes.json`, `object_tags.json`, `object_import_report.json`. `load` за одну транзакцию загружает базовые типы, обновляет объекты по паре `source` + `external_id` и добавляет/обновляет атрибуты и теги. Повторный запуск не создаёт дубликаты. Для обновления исходных выгрузок сначала запустить `MOS_API_KEY=... uv run python -m scripts.import_city_objects.mos_api_client`; ключ в Git не записывается. После обновления исходных данных следует заново собрать seed и проверить этот отчёт.
