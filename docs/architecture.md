# Архитектура тренажёра

**Статус:** описание текущих границ приложения; планы и недостающие проверки — в [текущем состоянии](current-state.md). Основание выбора стека — [ADR-001](decisions/ADR-001-foundation.md).

## Стек и границы

Модульный монолит: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL; React, Vite, CSS Modules. Backend хранит бизнес-правила, проверяет роли и команды. REST возвращает каноническое состояние и историю; Socket.IO уведомляет об изменениях, после reconnect клиент повторно запрашивает REST. Время и учебные нормативы вычисляет сервер. Локальный запуск — `dev.py`, чистое развёртывание данных — `app.scripts.bootstrap_demo`.

Для MVP backend запускается одним worker/process. PostgreSQL advisory lock дополнительно защищает scheduler от случайного параллельного запуска, но многопроцессный режим не является поддерживаемой конфигурацией учебного стенда.

```text
React → REST / Socket.IO → FastAPI
                         ├─ identity / admin
                         ├─ training / assessment
                         ├─ scenario_library / object_registry
                         └─ incidents / response
                                      ↓
                                  PostgreSQL
```

## Занятие и карточки

`TrainingSession` задаёт режим `FLOW`, `FIXED_SET` или `MANUAL`, порядок выдачи и группы участников. `TrainingRun` представляет одного обучаемого на всю смену. `TrainingGroup` задаёт состав и групповые настройки. Преподаватель выбирает постоянные группы и готовит групповые карточки до подключения обучаемых; `TrainingRun` появляется после занятия АРМ. Правила активного занятия — в [концепции преподавателя](instructor-workspace-concept.md).

`ScenarioTemplate` — методическая основа: тип происшествия, правило выбора объекта, сложность и допустимые условия. `ScenarioInstance` сохраняет конкретный snapshot классификатора, объекта, служб, условий и текста. `ScenarioQueueItem` хранит подготовленный пул. Внутренние статусы шаблона и экземпляра не являются обязательными шагами UI. `FLOW` выдаёт карточки по учебному времени, `FIXED_SET` — подготовленный набор при запуске, `MANUAL` — по команде преподавателя. Scheduler блокирует строку занятия на время выдачи; повторный тик не создаёт вторую карточку. В `Incident.source_snapshot` копируется подготовленное содержимое, поэтому последующие изменения шаблона не меняют выданную карточку. Действующая предметная модель — в [библиотеке и генераторе](scenario-library-and-generator.md); [Scenario Engine](scenario-engine.md) описывает legacy/internal слой событий.

Общий пул адресован `TrainingGroup`: первый успешный условный claim назначает карточку одному `TrainingRun`, второй конкурентный запрос получает конфликт. Остальные участники сохраняют просмотр. Индивидуальный пул адресован участнику. Доступ к карточке проверяется по занятию и группе, изменение — по владельцу. Socket.IO уведомляет, клиент перечитывает REST.

Глобальная и личная паузы исключаются из учебного времени без двойного вычитания пересечений. `GRACEFUL` прекращает выдачу и позволяет закончить взятое; `IMMEDIATE` завершает занятие сразу. Преподавательские команды сохраняются как `InstructorAction`, заметки — как `InstructorNote`; преподаватель не создаёт `IncidentAction` от имени обучаемого. Подробные переходы — в [автоматах состояний](state-machines.md).

## Справочники и генерация

SRC-006 хранится как правила классификатора, признаки и подтверждённые связи со службами. Неоднозначные соответствия не угадываются. `ObjectRegistry` содержит дерево типов, объекты, атрибуты и семантические теги; выбор объекта не определяет автоматически тип происшествия или службу. Правила реестра и качество источников — в [документе реестра](object-registry.md). Будущая маршрутизация должна учитывать классификацию, район обслуживания и подчинённость объекта; сейчас используются подготовленные связи и сценарные данные.

`AITextRenderer` принимает структурированные факты, вызывает OpenAI либо OpenAI-compatible adapter с таймаутом и fallback, валидирует текст и сохраняет его в snapshot до занятия. AI формулирует текст карточки и резюме оценки, но не выбирает бизнес-факты, службы, реакции, переходы статусов или правильные действия. Настройки задаются окружением или `/api/admin/ai`; ключ остаётся на backend. Runtime тренировки не зависит от доступности AI.

## ДДС и виртуальная группа

`Incident` хранит технический lifecycle отдельно от предметного статуса ДДС. Backend возвращает `available_actions` и сохраняет неизменяемую хронологию `IncidentAction` с серверным временем. После принятия карточки другие службы из snapshot дают детерминированную первичную реакцию; бригада 101 выпускает четыре этапа по учебному времени. `IncidentActivity` фиксирует эти сообщения как факты истории. Состояние бригады не переводит статус ДДС автоматически: обучаемый читает сообщение и выполняет действие сам. Старые `ResponseAssignment`, `ResponseMessage` и выпуск `ScenarioRuntimeEvent` сохраняются для совместимости, но не задают обычный MVP workflow. REST хранит каноническую историю, Socket.IO сообщает об изменениях.

## Оценивание и администрирование

После завершения занятия `AssessmentResult` фиксирует рассчитанные по истории метрики и отклонения: первичное решение, реакции на четыре этапа бригады, последовательность ручных статусов и завершение карточки. AI может сформулировать summary только по этим фактам. Преподаватель добавляет комментарий и подтверждает итоговую оценку; `AssessmentAudit` сохраняет каждое решение. Обучаемый видит только подтверждённый результат.

Административная граница — `/admin` и `/api/admin`; каждый endpoint проверяет роль `ADMIN` на backend. Модуль управляет пользователями, группами, классификатором, службами, объектами, библиотекой сценариев и AI. Изменения журналируются в `AdminAudit`, импорт — в `ImportRun`. Последнего активного администратора нельзя лишить доступа; пароли и AI-ключи не возвращаются клиенту. Подробности — в [панели администратора](admin-workspace.md).

Схема меняется только через Alembic. Нормативные, объектные и демонстрационные данные восстанавливаются из версионированных seed/import-файлов; runtime-история туда не входит. Импорт по устойчивым ключам идемпотентен и не удаляет исчезнувшие строки автоматически. Команды — в [воспроизводимых данных](database-seeding.md).
