# Вопросы заказчику

## Статусы

- `OPEN` — ответа нет;
- `CONFIRMED` — подтверждено ответом или профильным источником;
- `PRODUCT_DECISION` — решено командой для MVP.

## Закрытые ключевые вопросы

### Q-021 — Как ДДС организует реагирование после `Принята`?

**Status:** `CONFIRMED`  
**Ответ:** 21.09.2026.

Заказчик сообщил:

- используются доступные средства связи от телефона до внутренних каналов;
- для проекта ограничиваемся телефоном;
- решение принимает диспетчер, если имеет полномочия, иначе руководство;
- внутренний процесс у разных служб свой.

Следствие: продукт не должен моделировать единую внутреннюю организационную схему всех ДДС.

### Q-022 — Откуда ДДС получает сведения для статусов хода работ?

**Status:** `CONFIRMED`  
**Ответ:** 21.09.2026.

Старший группы реагирования:

- сам звонит в ДДС и докладывает об обстановке и ходе работ;
- либо диспетчер сам через некоторое время связывается со старшим и уточняет состояние.

Для оперативных служб также используется радиостанция, но MVP ограничивается телефонной моделью.

### Q-024 — По какому принципу службы попадают в список оповещения?

**Status:** `CONFIRMED`  
**Ответ:** 21.09.2026.

Учитываются район обслуживания и подчинённость объекта, а также профиль реагирования.

Пример заказчика: пожар в школе района Щукино с пострадавшими может оповестить 01/02/03, ДДС Департамента образования, ДДС управы Щукино и ДДС СЗАО.

## Актуальные открытые вопросы

### Q-023 — Какие исходные поля карточки ДДС может редактировать?

**Status:** `OPEN`

Точно подтверждены собственные статусы и комментарии. Полный набор редактируемых исходных полей не установлен.

### Q-025 — Что делает ДДС при обнаружении ошибки в карточке?

**Status:** `OPEN`

Подтверждено, что карточку нужно проверять и значимую ошибку, например в адресе, нужно заметить. Не подтверждён точный дальнейший процесс: исправление самим диспетчером, комментарий, связь с 112 или другой вариант.

### Q-026 — Какие ДДС берём в первую демонстрационную выборку?

**Status:** `OPEN / PRODUCT`

Нужно выбрать ограниченный набор показательных служб вместо попытки воспроизвести все варианты сразу.

## Решение MVP, не требующее ответа заказчика

### VIRTUAL-RESPONSE-UNIT

**Status:** `PRODUCT_DECISION`

Для первого MVP:

- реагирующая группа виртуальная;
- обучаемый назначает её вручную;
- коммуникация реализуется онлайн-чатом;
- чат имитирует телефонный обмен;
- группа может сама присылать доклады либо отвечать на инициативный запрос обучаемого;
- состояние группы не меняет статус карточки автоматически.
