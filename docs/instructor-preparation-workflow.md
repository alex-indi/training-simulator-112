# Целевая подготовка занятия преподавателем

**Статус:** источник требований для UT112-42.1–42.4; ещё не реализовано полностью.
**Область:** постоянные группы, подготовка занятия и карточек до подключения АРМ, библиотека сценариев, запуск.
**Текущее поведение:** см. [состояние `main`](current-state.md). Проведение активного занятия, монитор и разбор описаны [отдельно](instructor-workspace-concept.md).

## Главный принцип

Преподаватель полностью готовит занятие, пока нет подключённых обучаемых, занятых АРМ и `TrainingRun`. Подключение класса и запуск происходят после проверки материала.

```text
Постоянные группы + библиотека сценариев
→ параметры занятия → группы → карточки → подключение и запуск
→ Live Monitor → разбор
```

## Сущности и ответственность

- `UserGroup` — постоянная группа существующих пользователей `TRAINEE`: название, короткий код, состав, автор и признак архива. Она переиспользуется между занятиями; сложность и карточки в ней не хранятся. Преподаватель работает со своими группами, ADMIN сохраняет административные права. Через этот интерфейс преподаватель не меняет логины, пароли и роли.
- `TrainingGroup` — участие постоянной группы в конкретном `TrainingSession`, связь через `source_user_group_id`. Здесь находятся сложность, режим пула и подготовленные карточки. Группу можно быстро создать внутри занятия; она также появляется среди постоянных групп. Использованную постоянную группу архивируют, а не удаляют физически; архивные группы не предлагаются по умолчанию для новых занятий.
- `ScenarioInstance` — проверенное содержание карточки для группы занятия. Его создают и утверждают до `TrainingRun`; при необходимости можно добавить лёгкие метаданные партии. Новый универсальный Pack framework не требуется.
- `TrainingRun` появляется только после входа обучаемого и занятия им АРМ. Для выбора групп, генерации, просмотра и утверждения карточек он не нужен.

## Интерфейс подготовки

Основное меню преподавателя: «Занятия», «Группы обучающихся», «Библиотека сценариев». Раздел групп поддерживает поиск, просмотр состава, создание, правку названия/кода/состава, архивирование и просмотр архива. В группу добавляют существующих обучаемых.

### 1. Параметры занятия

Название предлагается автоматически и редактируется. В обычном UI доступны «Потоковая тренировка» (`FLOW`) с продолжительностью и интервалом выдачи и «Набор карточек» (`FIXED_SET`) без обязательной продолжительности. Порядок: по порядку или случайный порядок **уже подготовленных** карточек. Тема, число рабочих мест и `MANUAL` не показываются в этом основном потоке; удалять их из БД необязательно. После сохранения черновика интерфейс сразу открывает шаг «Группы».

### 2. Группы

Преподаватель выбирает существующие постоянные группы или создаёт группу в модальном окне без потери контекста. Для каждой `TrainingGroup` задаются понятная человеку сложность и «Общий пул» (`SHARED_QUEUE`) либо «Личный пул» (`INDIVIDUAL_QUEUE`). Эти настройки принадлежат занятию: одна постоянная группа в разных занятиях может иметь разные настройки. Подключённых людей пока может быть ноль.

### 3. Карточки происшествий

По каждой группе видны выбранные шаблоны и число подготовленных карточек. Одна группа может получать карточки из нескольких `ScenarioTemplate`; новая партия **добавляется** к уже подготовленной. «Добавить карточки по сценарию» открывает компактный Scenario Picker с поиском и кнопкой создания шаблона. Picker получает `training_session_id` и `training_group_id`, поэтому не спрашивает занятие, группу, АРМ или пользователя повторно.

Новый шаблон из Picker открывается в том же `ScenarioEditor`, что и самостоятельная библиотека. После «Сохранить и использовать» он сохраняется в библиотеке, выбирается в Picker и возвращает преподавателя к исходной группе. После выбора шаблона достаточно указать количество карточек и, при необходимости, разнообразие объектов; дополнительные технические настройки в обычный поток не выводятся.

Генерация привязана к занятию, группе и шаблону; могут передаваться `count`, `different_objects` и `seed`. Она не требует `training_run_id`, номера АРМ или подключённого пользователя. Преподаватель просматривает каждую карточку, исправляет условия и текст, перегенерирует только текст или всю карточку, исключает неподходящие экземпляры и утверждает набор. Перегенерация текста сохраняет структурированные факты; перегенерация карточки может менять разрешённые шаблоном факты и заново создаёт текст. Ручная правка текста не меняет факты.

### Библиотека сценариев

Самостоятельный раздел содержит «Создать сценарий» и полноценный параметрический редактор: название, тип происшествия и объекта, сложность по умолчанию, вариативные параметры, службы и их работу. Преподаватель задаёт структуру, а не пишет исходный текст каждой карточки.

- `DRAFT` редактируют преподаватели и администраторы по действующей политике.
- `READY` используют без правки на месте; действие «Изменить» создаёт новый `DRAFT` и открывает редактор.
- `READY` архивирует только автор или ADMIN; чужой преподаватель не может.
- Архивные шаблоны показываются отдельно.

В обычном интерфейсе показывают понятные названия, а не коды SRC-006, enum или имена классов. Технические значения остаются в backend и диагностической админке.

### AI и тексты

Вариантный генератор определяет структурированные факты, а `AITextRenderer` формулирует текст. AI не выбирает тип происшествия, объект, службы, число пострадавших, правильные действия или оценку. Тексты карточек и сообщений служб готовятся до занятия; runtime не зависит от внешнего AI. Текст карточки похож на короткую рабочую запись оператора: 1–3 простые фразы, только переданные факты, без канцеляризмов и без искажения адресов, чисел и названий. Сообщения служб имеют отдельный стиль краткого оперативного канала.

### 4. Подключение и запуск

Только здесь показываются фактически подключившиеся АРМ. При входе пользователя система сопоставляет его `UserGroup` с `TrainingGroup.source_user_group_id` текущего занятия. Если соответствия нет, обучаемый остаётся «Не распределён». Преподаватель может временно назначить его в другую группу этого занятия, не меняя постоянную `UserGroup`.

Перед стартом видны группы, участники, нераспределённые люди, готовность карточек и режим пула. При запуске утверждённый **общий пул** используется один раз на группу с атомарным claim. При **личном пуле** каждый `TrainingRun` получает полную независимую runtime-копию проверенного набора; повторный вызов AI и изменение фактов не нужны. Статусы, чат, время и результат каждого обучаемого независимы. После старта преподаватель переходит в Live Monitor.

## Критерии приёмки

1. При нуле подключённых АРМ преподаватель создаёт занятие, выбирает две постоянные группы, задаёт им разные сложности и режимы пула.
2. Он может создать постоянную группу прямо из шага «Группы» и затем найти её в отдельном разделе.
3. Для одной группы он добавляет несколько партий из разных шаблонов, просматривает, исправляет и утверждает карточки без `TrainingRun`.
4. Библиотека позволяет создавать и редактировать `DRAFT`; «Изменить READY» открывает копию; архивирование READY ограничено автором и ADMIN.
5. Picker не спрашивает известный контекст повторно; новый шаблон возвращает к исходной группе; обычный UI не показывает технические коды.
6. Вошедшие обучаемые распределяются по постоянным группам; нераспределённые видны, временная ручная коррекция не меняет постоянный состав.
7. После запуска общий пул един для группы, а каждый участник личного пула получает весь проверенный набор. Атомарный claim и независимость runtime-состояния сохранены.

## Границы изменения

UT112-42.1 — постоянные группы и шаг «Группы»; UT112-42.2 — библиотека и Picker; UT112-42.3 — карточки по группам без АРМ; UT112-42.4 — подключение, распределение и запуск. Переиспользуются существующие Scenario Engine, редактор, общий пул, оценивание и Live Monitor. Телефония, новый AI framework и масштабная перестройка приложения не требуются.
