# Портативный офлайн-стенд

Для Windows 10/11 x64, macOS 13+ Intel и macOS 13+ Apple Silicon собираются отдельные ZIP-файлы. Архив содержит CPython 3.12.14, PostgreSQL 16.14, backend, миграции, seed-файлы, зависимости и готовый frontend. На целевом компьютере не требуются Docker, Python, Node.js или интернет.

## Запуск

1. Полностью распакуйте ZIP в любую папку, включая путь с пробелами.
2. Откройте `Start.cmd` на Windows или `Start.command` на Mac двойным щелчком.
3. Дождитесь семи понятных этапов загрузки. Окно покажет панель с адресом для этого ПК, адресами локальной сети и инструкцией. На другом устройстве откройте адрес локальной сети в браузере.
4. Для остановки нажмите Enter в окне запуска. Повторный запуск, пока стенд работает, открывает тот же адрес.

При первом разрешении доступа из локальной сети Windows/macOS может показать запрос файрвола. Mac без Apple Developer ID может потребовать ручное разрешение запуска в настройках безопасности. Интернет после распаковки не используется. Для создания текстов применяется шаблонный режим.

Технические сообщения миграций, загрузки демоданных и веб-сервера не засоряют окно запуска. Журналы и подробности ошибок находятся в папке `logs` рядом с данными пользователя. При ошибке окно указывает этап и путь к `startup.log`.

Если на компьютере несколько сетевых адаптеров, Windows сначала показывает адрес активного физического подключения. Остальные адреса доступны в панели как запасные варианты.

Данные и результаты хранятся в `%LOCALAPPDATA%\UT112` на Windows и `~/Library/Application Support/UT112` на macOS. Данные Docker не импортируются. Перенос распакованной папки не переносит базу: она остаётся в профиле пользователя. Не удаляйте эту папку профиля, если результаты нужны. Перед обновлением версии приложения автоматически создаётся копия каталога PostgreSQL в `backups`; если новая версия PostgreSQL несовместима с базой, запуск останавливается без удаления данных.

На Windows при запуске из папки с кириллицей бинарники PostgreSQL однократно копируются в ASCII-путь внутри `%LOCALAPPDATA%\UT112`. Это обходит ограничение `initdb` на путь к исполняемому файлу. Если сам путь к профилю пользователя содержит кириллицу, PostgreSQL также требует отдельный ASCII-путь для базы; launcher сообщит об этом и предложит задать `UT112_PORTABLE_DATA_DIR` перед запуском.

PostgreSQL слушает только `127.0.0.1`; веб-сервер принимает соединения из локальной сети. Для портов веб-сервера сначала проверяются 8080–8099, затем выбирается свободный порт ОС. Пароль базы находится только в профиле пользователя, в `database.json`.

## Сборка

CI workflow `.github/workflows/portable.yml` собирает каждый ZIP на соответствующей платформе и прикрепляет его к запуску workflow. Для локальной сборки на Windows: `python scripts/build_portable.py --target windows-x64`. Аналогично используются `macos-x64` и `macos-arm64` на соответствующих Mac. Сборщику нужны интернет, Python 3.12, Node.js 22 и `uv`; пользователю готового ZIP они не нужны.

Исходные архивы CPython и PostgreSQL закреплены версиями и SHA-256 в `scripts/build_portable.py`. Зависимости Python берутся из `backend/uv.lock` с проверкой хешей, frontend — из `frontend/package-lock.json`; их SHA-256 и commit приложения записываются в `COMPONENTS.json` каждого ZIP.

Smoke-тест распакованного архива: `python scripts/smoke_portable.py dist/UT112-windows-x64.zip` (либо соответствующий Mac ZIP). Он проверяет первый запуск, маршруты страницы/API/Socket.IO, занятый порт, повторный запуск, сохранение записи БД, перезапуск и перенос папки. Доступ нескольких физических устройств в LAN и поведение при отключённой сети проверяются на целевых компьютерах вручную.
