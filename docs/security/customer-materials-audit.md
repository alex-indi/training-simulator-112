## Если владелец одобрит переписывание истории

1. Согласовать окно остановки push/merge и сохранить резервную копию всех refs у владельца. Сверить branches, tags, PR refs и форки на GitHub; оценить раскрытие материалов и необходимость уведомления заказчика.
2. В отдельном зеркальном clone использовать `git filter-repo` с удалением обоих путей: `materials/customer.zip` и `materials/customer/` из всех согласованных refs. Сначала проверить результат локально; исходный репозиторий и эту рабочую ветку не переписывать.
3. Проверить отсутствие путей через `git rev-list --objects --all`, повторить secret scan и проверить build/CI на переписанной истории.
4. После согласования с командой обновить remote refs принудительно с защитой от гонок и обеспечить удаление/истечение GitHub cached PR refs по правилам площадки. Старые SHA, ссылки на commits и открытые PR станут недействительными. Клонам и веткам участников потребуется re-clone или перенос собственных изменений через cherry-pick поверх новой истории; обычный pull не решит расхождение.
5. Даже после rewrite считать содержимое потенциально уже полученным третьими лицами. При выявлении действующих credentials их следует отозвать независимо от rewrite.
