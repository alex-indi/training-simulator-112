## Каталог служб

Документ состоит из 55 скриншотов окна «Добавьте службы», а не машиночитаемой таблицы. Названия извлечены из видимых строк списка, повторяющиеся при прокрутке строки сведены к одной записи. Найдено **209 различных записей**: 157 записей с явно указанной ДДС и 52 другие службы или организации. Среди них 156 названий начинаются с «Поселение», 10 — с «ГБУ АД». Эти слова сохранены как часть исходного интерфейсного названия и не заменены административной классификацией.

`official_name` содержит видимое в каталоге название целиком. `organization` заполняется текстом в скобках, если он присутствует; `service_level` получает значение `ДДС` только при явном упоминании ДДС в этой части строки. `source_reference` указывает на изображение и строку списка внутри DOCX. Семь искажённых OCR фрагментов сверены с изображениями вручную, в том числе названия 101, 104, ЦЭМП, ЦОДД и ЭВАЖД.

## Связи и неоднозначности

Связи построены по колонке M «Главная служба». Коды сопоставлены с краткими названиями, явно присутствующими в каталоге: например `MCHS` → `Служба 101`, `Police` → `Служба 102`, `AMBULANCE` → `Служба 103`. Составные значения разделены на две подтверждённые службы. Список соответствий хранится в `backend/seed/incident_classifier/extract_rule_services.py`.

- Подтверждено **1 179 связей** для **1 176 правил** и **22 служб**. **107 правил** пока не имеют связи.
- У 103 правил колонка M пуста или содержит только пробел. Для них служба не подставлялась по догадке.
- Коды `GKH` (3 правила) и `МСР` (1 правило) не имеют однозначного соответствия названию каталога; в MVP для них связь не создаётся.
- В колонках N–CG есть классификаторы и условия для многих других ведомств. Они не превращены в дополнительные связи: заполненная ячейка может означать условное оповещение, тип сообщения или служебную отметку. Дополнительные связи не входят в MVP.
- Каталог представлен скриншотами; перед эксплуатационным использованием нужен просмотр заказчиком извлечённых названий, прежде всего OCR транскрипции районных ДДС и официальных наименований организаций.

## Воспроизведение

Из корня проекта с Python и `openpyxl`:

```bash
PYTHONPATH=backend python -m seed.incident_classifier.extract_src006 materials/customer/SRC-006-incident-classifier-v046-24.xlsx
PYTHONPATH=backend python -m seed.incident_classifier.extract_rule_services materials/customer/SRC-006-incident-classifier-v046-24.xlsx
```

`services.json` — OCR-транскрипция каталога с выборочной ручной сверкой строк, где распознавание дало явные артефакты. После миграции БД запуск `cd backend && python -m seed.incident_classifier.import_seed` выполняет вставку или обновление по исходным ключам. Повторный запуск не добавляет дубликаты. Seed не меняет существующие карточки `Incident`.

Локальная БД проекта обновлена до Alembic revision `20260924_09`; seed импортирован. Фактические количества после импорта: 1 283 правила, 1 024 признака, 209 служб, 2 816 связей правил с признаками и 1 179 связей правил со службами.

Проверочные read-only маршруты: `GET /incident-classifier/types`, `/features`, `/services` и `/rules/{id}`. Последний маршрут возвращает признаки, службы и ссылки на источники для конкретного правила.
