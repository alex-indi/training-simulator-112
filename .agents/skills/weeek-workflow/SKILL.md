# WEEEK workflow — простой режим

## Доска

Используются только три колонки:

```text
К работе → В работе → Готово
```

Не требуй Review, QA, Controller, Blocked или дополнительных обязательных колонок.

## Начало задачи

Когда пользователь говорит:

```text
Начни задачу UT112-12
Возьми UT112-12
```

выполни **весь start workflow**. Не передавай создание ветки `project-resume`.

### 1. WEEEK

1. найди задачу;
2. убедись, что она находится в `К работе` или уже принадлежит текущему пользователю;
3. проверь исполнителя;
4. если задача назначена другому разработчику — не перехватывай её;
5. если исполнитель не задан — назначь текущего пользователя;
6. переведи задачу в `В работе`.

### 2. Git preflight

Выполни:

```bash
git status --short --branch
git branch --show-current
```

Определи тип ветки:

- новая функциональность → `feature`;
- исправление ошибки → `fix`;
- только документация → `docs`;
- служебная/инфраструктурная задача → `chore`.

Если тип неочевиден — используй `feature`.

Сформируй короткий slug на английском.

### 3. Обязательная ветка

Если текущая ветка уже содержит нужный `UT112-12`, оставь её.

Если текущая ветка `main`:

- при чистом рабочем дереве сначала:
  ```bash
  git pull --ff-only
  ```
- затем:
  ```bash
  git switch -c <type>/UT112-12-short-slug
  ```

Если подходящая локальная ветка уже существует:

```bash
git switch <existing-branch>
```

Если существует только remote-ветка, создай локальную tracking-ветку обычным безопасным Git-способом.

### 4. Проверка — обязательна

После switch/create выполни:

```bash
git branch --show-current
```

Продолжай только если имя текущей ветки содержит `UT112-12`.

Если ветка не создана или не переключилась:

- не изменяй файлы задачи;
- не создавай task handoff как будто старт успешен;
- сообщи пользователю, что именно помешало.

### 5. Handoff и работа

Только после успешного Git-gate:

1. создай/обнови `tasks/UT112-12.md`;
2. прочитай `docs/current-state.md`;
3. прочитай только нужные документы;
4. сообщи пользователю одной строкой:
   ```text
   UT112-12 взята в работу. Ветка: <branch>.
   ```
5. начинай реализацию.

## Продолжение существующей задачи

Для уже начатой задачи используй `$project-resume`.

Не создавай новую ветку, если текущая корректная ветка уже содержит Task ID.

## Блокировка

Отдельной колонки нет.

Если работа заблокирована:

- оставь задачу в `В работе`;
- кратко запиши причину в handoff.

## Завершение

Фраза:

```text
Задача готова, проверь всё
```

не означает автоматический перевод в `Готово`.

Сначала должны быть выполнены проверки проекта и показан результат пользователю.

Только после явного подтверждения:

```text
Всё работает, заверши задачу
Можно в готово
Закрывай задачу
```

переведи:

```text
В работе → Готово
```

## Исполнитель

У каждой задачи один основной исполнитель.

Не меняй исполнителя без понятной причины или явного запроса.

## Если MCP недоступен

Не блокируй разработку.

Сообщи одной фразой:

```text
WEEEK сейчас не синхронизирован, продолжаю по Git и handoff.
```

## Безопасность

- не удаляй задачи;
- не изменяй массово несколько задач;
- не двигай чужую задачу;
- не переводить задачу в `Готово` без подтверждения человека;
- не начинать изменения новой задачи на `main`.
