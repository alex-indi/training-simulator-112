# Материалы заказчика

Используй этот skill для точечного изучения исходных документов заказчика.

Не загружай все материалы одновременно.

## Порядок работы

1. Сформулируй конкретный вопрос, на который нужно ответить.
2. Прочитай [references/catalog.md](references/catalog.md).
3. Выбери минимальное количество подходящих источников.
4. Открой только выбранные документы.
5. Найди сведения, непосредственно относящиеся к вопросу.
6. Отдели факты от интерпретаций и проектных решений.
7. Укажи использованные источники и точное место внутри них.
8. Зафиксируй противоречия и отсутствующие сведения.

## Работа с форматами

Для PDF используй извлечение текста и визуальную проверку нужных страниц.

Для DOCX со скриншотами обязательно проверяй изображения. Извлечённого текста
недостаточно для выводов об интерфейсе.

Для XLSX анализируй только нужные листы, столбцы и строки. Не загружай весь
классификатор, если задача относится к отдельной категории.

Не делай выводы о содержании документа только по его имени.

## Правила доказательности

Для каждого существенного вывода указывай:

- идентификатор источника;
- название документа;
- страницу, раздел, лист, диапазон строк или номер скриншота;
- тип вывода: факт, наблюдение, интерпретация или проектное решение.

Используй следующий формат:

```text
Источник: SRC-002, «Работа с АРМ-112 для ДДС», стр. 14.
Тип: FACT.
Вывод: ...
```

Для сведений со скриншота:

```text
Источник: SRC-004, «Скриншот ДДС», скриншот 3.
Тип: OBSERVATION.
Наблюдение: ...
```

## Типы выводов

- `FACT` — явно указано в тексте источника.
- `OBSERVATION` — непосредственно видно на скриншоте или в таблице.
- `INFERENCE` — логический вывод из нескольких фактов или наблюдений.
- `DESIGN_DECISION` — решение команды о реализации продукта.
- `OPEN` — источник не позволяет сделать однозначный вывод.

Не представляй `OBSERVATION` или `INFERENCE` как подтверждённое
бизнес-правило.

## Приоритет источников

При оценке бизнес-процесса учитывай назначение источника:

1. прямые ответы заказчика;
2. рабочие инструкции;
3. материалы, описывающие работу АРМ ДДС;
4. классификаторы и справочники;
5. учебные билеты и примеры;
6. отдельные скриншоты;
7. презентационные материалы.

Более высокая позиция не отменяет проверку даты и актуальности документа.

Если источники расходятся, не выбирай один самостоятельно. Опиши расхождение
и сформулируй вопрос заказчику.

## Использование результатов

Не изменяй проектные документы только из-за вызова skill.

Если текущая задача предусматривает обновление документации:

- подтверждённые бизнес-факты переноси в `docs/domain.md`;
- открытые вопросы переноси в `docs/questions/customer-questions.md`;
- архитектурные решения оформляй отдельно от требований заказчика;
- сведения об интерфейсе используй как референс, а не как требование
  полного визуального копирования.

Не копируй в проектную документацию большие фрагменты исходных документов.
Сохраняй короткий вывод и ссылку на источник.
