# Материалы заказчика

Используй этот skill только для проверки конкретного предметного вопроса.

## Порядок

1. Сформулируй один проверяемый вопрос.
2. Прочитай `references/catalog.md`.
3. Выбери минимальный набор источников.
4. Извлеки только относящиеся к вопросу фрагменты/скриншоты/строки.
5. Раздели результат на `FACT`, `OBSERVATION`, `INFERENCE`, `DESIGN_DECISION`, `OPEN`.
6. При расхождении источников не выбирай трактовку догадкой.
7. Если вопрос уже подтверждён в `docs/domain.md`, не перечитывай источники без причины.

## Форматы

- PDF: текст + визуальная проверка нужных страниц.
- DOCX со скриншотами: обязательно проверять изображения, а не только extracted text.
- XLSX: анализировать только нужные листы/колонки/строки.
- JSON Q&A-чата: искать сообщения по теме, сохранять автора, дату, id сообщения и ближайший контекст; отличать сообщения участников от ответов администратора/заказчика.

## Доказательность

Пример:

```text
Источник: SRC-014, Q&A chat export, message 684, 21.09.2026.
Тип: FACT.
Вывод: заказчик подтвердил ...
```

Для скриншота:

```text
Источник: SRC-013, «СЛУЖБЫ 112», screenshot N.
Тип: OBSERVATION.
Наблюдение: ...
```

## Приоритет

1. свежий прямой ответ заказчика;
2. профильная инструкция ДДС;
3. документы реального АРМ;
4. QA-ответы;
5. классификаторы/справочники;
6. учебные примеры;
7. отдельные скриншоты.

Свежий ответ не отменяет необходимость учитывать контекст вопроса.

## Перенос результатов

Если задача предусматривает актуализацию проекта:

- факт → `docs/domain.md`;
- открытый вопрос → `docs/questions/customer-questions.md`;
- product choice → `docs/decision-log.md` / `docs/product.md`;
- архитектурное последствие → `docs/architecture.md` или ADR.

Не копируй большие фрагменты материалов в Git.
