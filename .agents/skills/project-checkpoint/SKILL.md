# Project Checkpoint

Сохрани работу так, чтобы её можно было продолжить на другом устройстве.

1. Определи текущую ветку и посмотри `git status --short --branch`, `git diff --stat` и diff относящихся файлов.
2. Обнови краткий handoff: используй существующий `tasks/UT112-XX.md` или создай файл в `tasks/`, заменив `/` в имени ветки на `-`. Запиши сделанное, оставшееся, блокеры, результаты проверок и **один точный следующий шаг**.
3. Выполни доступные короткие проверки, относящиеся к изменению. Полный прогон нужен перед итоговым коммитом, а не для промежуточного checkpoint.
4. Добавь в stage только относящиеся к работе файлы. Не добавляй `.env`, токены, материалы заказчика и случайные файлы.
5. Создай промежуточный commit и push текущей ветки. Сообщи хеш коммита, результат push и следующий шаг.

Не обращайся к WEEEK.
