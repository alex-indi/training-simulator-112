# Project Checkpoint

Цель — чтобы работу можно было открыть на другом устройстве и сразу продолжить.

## Что сделать

1. определить текущую ветку и `UT112-XX`;
2. посмотреть:
   ```bash
   git status --short --branch
   git diff --stat
   git diff
   ```
3. выполнить короткие известные проверки, если они доступны;
4. создать или обновить `tasks/UT112-XX.md`;
5. записать:
   - что сделано;
   - что осталось;
   - checks;
   - blockers;
   - **один точный следующий шаг**;
6. stage только относящиеся к задаче файлы;
7. не добавлять `.env`, токены, материалы заказчика или случайные файлы;
8. создать нормальный commit; если работа промежуточная:
   ```text
   chore(UT112-XX): сохранить промежуточное состояние
   ```
9. push текущей ветки;
10. кратко сообщить:
    - commit;
    - push успешен или нет;
    - следующий шаг.

Обычный checkpoint не меняет статус WEEEK: задача остаётся `В работе`.
