# Project Resume

Цель: продолжить работу без зависимости от предыдущего чата.

## 1. Никогда не восстанавливай старый чат

Не проси пользователя пересказывать старую сессию, если состояние можно получить из репозитория.

Не пытайся сжимать/пересказывать старый чат как основной способ восстановления.

## 2. Найди корень и состояние Git

Выполни безопасные read-only команды:

```bash
git rev-parse --show-toplevel
git branch --show-current
git status --short --branch
git log -8 --oneline --decorate
```

Не выполняй reset, checkout с потерей изменений, clean, rebase, stash pop или другие изменяющие команды.

## 3. Определи Task ID

Приоритет:

1. ID, явно указанный пользователем;
2. `UT112-xxx` в имени текущей ветки;
3. единственный `tasks/UT112-xxx.md` со статусом `IN_PROGRESS`.

Если однозначно определить задачу нельзя, покажи найденные варианты и спроси только Task ID.

## 4. Прочитай минимальный контекст

Всегда:

- `AGENTS.md`;
- `docs/current-state.md`;
- `tasks/UT112-xxx.md`, если найден.

Дальше читай только релевантные документы:

- предметные изменения → `docs/domain.md`;
- продукт → `docs/product.md`;
- архитектура → `docs/architecture.md` + ADR;
- причины прошлых решений → `docs/decision-log.md`;
- вопросы заказчику → `docs/questions/customer-questions.md`.

Не читай исходные материалы заказчика, если task handoff или задача не требуют их проверки.

## 5. Проверь незавершённую работу

Если working tree dirty:

```bash
git diff --stat
git diff
```

При staged changes также посмотри:

```bash
git diff --cached
```

Ничего не отменяй.

## 6. WEEEK — если MCP доступен

Получить задачу `UT112-xxx` и проверить:

- title;
- status;
- acceptance criteria;
- blockers / dependencies.

Если WEEEK недоступен, продолжай по Git/handoff и кратко отметь ограничение. Отсутствие MCP не должно блокировать восстановление.

## 7. Сверь источники

Проверь, не расходятся ли:

- task handoff;
- фактический Git diff;
- последние commits;
- WEEEK.

Git/diff определяет, что реально сделано. Handoff объясняет намерение. WEEEK определяет управленческий статус.

## 8. Выдай короткий resume

Перед продолжением сообщи не больше 8 пунктов:

- Task ID и ветка;
- цель;
- что уже сделано;
- есть ли локальные незакоммиченные изменения;
- результаты последних проверок;
- блокеры;
- exact next step.

Не пересказывай весь проект.

## 9. Продолжи

Если exact next step безопасен и понятен — приступай сразу.

Если обнаружено противоречие, способное изменить реализацию, остановись и задай один точный вопрос.
