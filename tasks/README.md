# Task Handoffs

`tasks/` хранит техническое состояние незавершённых задач.

## Зачем это нужно

Codex-сессия может зависнуть, быть закрыта или не существовать на другом устройстве. Task handoff позволяет продолжить работу без восстановления старого чата.

## Правило именования

```text
tasks/UT112-123.md
```

Файл соответствует задаче WEEEK и Git-ветке, содержащей тот же идентификатор.

## Что хранит WEEEK

- название и бизнес-цель;
- исполнитель;
- приоритет;
- Kanban status;
- acceptance criteria.

## Что хранит task handoff

- фактическое состояние реализации;
- сделанные изменения;
- затронутые файлы;
- проверки;
- локальные технические решения;
- блокеры;
- точный следующий шаг;
- последний checkpoint.

Не копируй в handoff всю документацию проекта и длинные логи.

## Жизненный цикл

При старте задачи:

1. скопировать `TEMPLATE.md` в `UT112-xxx.md`;
2. заполнить цель и acceptance criteria ссылкой/выжимкой из WEEEK;
3. создать ветку с тем же ID.

Во время работы файл обновляется только в значимые checkpoints.

После merge файл можно:

- оставить как компактный журнал задачи; либо
- переместить в будущий архив, если количество завершённых handoff станет большим.

На первом этапе оставляем в `tasks/`.
